# F2b Motor pi (pi.dev) — Requirements

## Context
F1 y F2a observan Claude Code y Codex CLI. F2b agrega el motor **pi** (CLI `pi` de pi.dev, formato de sesión `version: 3`) con dos carriles de PLAN.md §6.1: el carril A (tail pasivo de los JSONL de sesión que pi escribe en disco) y el carril B (una extensión de crow, instalada a nivel usuario con `crow attach pi`, que manda eventos en vivo a `/ingest/hook/pi`). pi no expone OTel, así que no hay carril C. Gemini CLI y OpenCode (carril D) quedan fuera de F2b.

Evidencia de partida: `.navori/state/handoffs/scout_pi-docs.md` (doc y tipos de pi 0.99.1) y `scout_pi-sessions.md` (estructura de dos sesiones reales, sin contenido).

## Requirements (EARS)

### Carril A: sesiones en disco
- **R1** — The system SHALL discover pi session files under the session root resolved as `PI_CODING_AGENT_SESSION_DIR` if set, else `$PI_CODING_AGENT_DIR/sessions` if `PI_CODING_AGENT_DIR` is set, else `~/.pi/agent/sessions` (the `sessionDir` setting of pi's `settings.json` is not followed; `crow doctor` reports it when set, see R16), and tail them with the same backfill, offset and partial-line rules as the other engines.
- **R2** — WHEN a pi session file is ingested, the system SHALL identify the session by the `id` of its `session` header entry and attribute it to the project given by the header's `cwd` under the `projectKey` rule, never by decoding the directory name.
- **R3** — The pi adapter SHALL map `message` entries to `CrowEvent`s: a `user` message to `prompt`, an `assistant` message's `toolCall` blocks to `tool.pre` and the end of its turn, after the tool results of its tool calls, to `turn.end`, a `toolResult` entry to `tool.post` paired to its call by `toolCallId`, and SHALL map `model_change` entries to a new `model.change` event kind and `compaction` entries to `compact`, without copying message text, thinking, tool arguments or tool output beyond the fields the existing engines already keep.
- **R4** — WHEN a pi session file entry carries model usage (an `assistant` or `toolResult` message, or a `compaction`, `branch_summary` or `usage` entry), the system SHALL record one `usage` for that model call, keyed so that the same call is never counted twice (by `responseId` when present, else by session id, entry id and entry type), with the token counts from the entry's usage and `costUsd` from its `cost.total` WHEN it is greater than 0, else from crow's own price table for the model the entry names (unpriced WHEN it names none), so that a session's token totals match pi's and its cost matches pi's for every call pi prices.
- **R5** — WHERE a session file contains branches (several entries with the same `parentId`), the system SHALL ingest every entry of the file once and SHALL count the usage of every model call in the file once, whatever branch it belongs to, except the entries inherited from a parent session under R6.
- **R6** — IF a session header carries a `parentSession` (a fork or clone), THEN the system SHALL treat the file as its own session, SHALL NOT count again the usage of model calls copied from the parent session, and SHALL NOT show the copied history in that session's timeline.
- **R7** — IF a session header carries a `version` other than 3, or an entry has a `type` the adapter does not know, THEN the system SHALL keep ingesting the rest of the file, count the unknown entries in `/api/stats`, and record one visible `ingest.error` per file and reason instead of failing silently.

### Carril B: extensión de crow
- **R8** — The crow extension for pi SHALL forward the pi extension events `session_start`, `session_shutdown`, `turn_start`, `turn_end`, `tool_call`, `tool_result`, `tool_execution_start`, `tool_execution_end`, `agent_end`, `session_compact` and `model_select` to `POST /ingest/hook/pi`, and the pi adapter SHALL map them to `CrowEvent`s with `source = "hook"` (the events `turn_start`, `agent_end`, `model_select` and the extension `reload` are forwarded but produce no event) attributed to the same project, session and agent as the carril A events of that run.
- **R9** — WHEN the same fact arrives more than once, through the session file and the extension or twice through the extension, the system SHALL keep one logical fact whatever the arrival order: one tool call (matched by the tool call id), one turn end (matched by the assistant message entry id), one compaction (matched by the compaction entry id) and one session start (matched by the session header, or for a resume by the session's leaf entry id at resume time).
- **R10** — The crow extension SHALL send only allowlisted fields (event name, session, entry and tool call ids, `cwd`, tool name, timestamps, durations, error flags, the closed enums `reason`, `source` and `stopReason`, model identifiers, and the envelope fields `v`, `turnIndex`, `willRetry` and `dropped`) and SHALL NOT send prompts, message text, thinking, tool arguments or tool output.
- **R11** — WHILE crow is not running, slow or rejecting requests, the crow extension SHALL NOT surface an error to the user, SHALL NOT block or alter any tool call, and SHALL add at most 2 s to any pi event handler.
- **R12** — WHERE an ingest token is configured, the crow extension SHALL send it with every request under the same rule as the other engines' hooks.

### CLI: `crow attach | detach | doctor pi`
- **R13** — WHEN the user runs `crow attach pi`, the system SHALL compute the change that installs the crow extension at pi's user level (never in an observed repo), show it as a diff, write nothing without explicit confirmation, save a timestamped backup of any file it overwrites, and leave an already attached installation unchanged.
- **R14** — WHEN the user runs `crow detach pi` and confirms, the system SHALL remove the crow extension if the user has not modified it, keep and report it if modified, and preserve every other pi setting and extension.
- **R15** — IF the pi configuration crow must read or change cannot be parsed THEN `attach` and `detach` SHALL abort with the reason and SHALL NOT write anything.
- **R16** — WHEN the user runs `crow doctor`, the system SHALL report for pi the session root and whether it exists, the session files seen, whether the crow extension is installed and unmodified, the last extension event received, and a warning WHEN pi's `settings.json` sets a `sessionDir` crow does not follow or excludes the crow extension, WHEN the installed extension targets a port or token file other than crow's current ones, or WHEN the extension is installed but no event arrived while pi sessions are live.

### Integración
- **R17** — The system SHALL register `pi` as an engine so that its sessions appear in the project grid, split view and session detail with the same cost panel and the same live behavior as the other engines: `live` and `idle` from either lane, and `ended` only WHEN the crow extension reports the session's shutdown, since pi's session file has no end marker.
- **R18** — The pi fixtures committed to the repo SHALL be anonymized with an allowlist of structural keys (no prompts, message text, thinking, tool arguments, tool output, paths outside rewritten `cwd`s, or credentials), enforced by `fixtures/hygiene.test.ts`.
